# Maintenance

Dependabot proposes npm, Python, and GitHub Actions updates weekly. The Check workflow runs lint, unit tests, package checks, and shexli static analysis on changes and on demand. The ZIP is uploaded only after these checks pass. Tested extension ZIPs are named by checkout SHA and retained for 14 days, with download links in the Actions summary. GNOME Shell compatibility still needs validation in a real session before publishing an extension update.

The analyzer is the official [shexli from extensions-web](https://gitlab.gnome.org/Infrastructure/extensions-web/-/tree/master/shexli), installed from the published `shexli==0.2.1` package. `requirements-shexli.txt` pins the analyzer and both parser dependencies. A fresh install with tree-sitter 0.26.0 and tree-sitter-javascript 0.25.0 segfaults on our ZIP; tree-sitter 0.25.2 works. Review these pins together when updating the analyzer.

`scripts/check-shexli.py` checks the structured analysis result because the upstream CLI returns success even when it reports errors. Every finding, including warnings, fails the gate except one exact diagnostic: shexli 0.2.1's `EGO-M-004` rejects our `['45', '46', '47', '48', '49', '50', '51']` declaration because its metadata rule hardcodes 50 as the maximum version. This remains present in upstream commit `e053667b046ba8a9dbfd74503fdd0f5dc90939c5`. The exception matches the rule, severity, message, and complete metadata evidence; other invalid version declarations still fail. Remove it and update the corresponding test once upstream supports GNOME 51. Do not remove GNOME 51 from the shipped metadata to satisfy this outdated limit.

The unfiltered JSON report, including that exception, is retained as a separate `shexli-<SHA>` Actions artifact for 14 days, including when analysis finds a blocking issue. A crash or missing analyzer also fails the job. After packaging, `npm run test:shexli` exercises the gate with real scans of clean, warning-producing, and invalid ZIPs. Use the Python environment from the README for these commands.

GitHub repository settings also enable dependency vulnerability alerts, Dependabot security updates, and weekly CodeQL default setup. Security updates propose pull requests; they do not merge them or publish app releases. The default CodeQL configuration lives in GitHub settings, alongside these versioned maintenance workflows.
